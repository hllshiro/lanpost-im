# 文档索引

文档按用途分为四类。新增或调整文档时，先判断它描述的是“为什么这样设计”“现在是什么状态”“接下来做什么”还是“可查阅的资料”，再放入对应目录。版本变更记录在仓库根目录的 `CHANGELOG.md`。

## 01-设计

长期有效的设计基线、架构决策和模块边界。

- [标准 IPMSG 0.1.0 设计（2026-10-26）](superpowers/specs/2026-10-26-ipmsg-standard-0.1.0-design.md)
- [Electron 客户端设计（2026-10-23，历史）](01-设计/2026-10-23-electron-client-design.md)（已被 0.1.0 设计取代，仅作历史参考）

## 02-现状

当前实现状态、已知限制和故障边界。这里的内容应随代码更新。

- [已知限制与当前边界](02-现状/known-limits.md)

## 03-计划

进行中的计划。当前没有进行中的计划。

- [计划目录说明](03-计划/README.md)

已完成或已放弃的计划不保留空文档；仍有验证或加固事项的，并入 `02-现状/known-limits.md`。

- [文件传输状态机与故障排查](04-参考资料/file-transfer.md)

## 维护约定

- 设计变更先更新 `01-设计`，再同步 `02-现状`。
- `03-计划` 只放仍在推进的事项；完成或放弃后删除文档，未完成的验证项并入 `02-现状/known-limits.md`。
- 抓包、协议字段和兼容矩阵放在 `04-参考资料`；排查步骤可以同时出现在现状文档和参考资料中，但以参考资料为准。
- 文档中的路径统一使用仓库根目录相对路径，例如 `docs/04-参考资料/file-transfer.md`。
- 不提交包含真实账号、主机名、聊天内容或未脱敏的 pcap。
