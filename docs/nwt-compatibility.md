# 内网通兼容矩阵

目标对端是真实内网通 3.4.3055。本客户端只使用内网通 NWT 私有协议，不实现 IPMSG、飞秋、飞鸽兼容。

## 兼容矩阵

| 能力                   | 真实内网通 ↔ 本客户端 | 本客户端 ↔ 本客户端 | 说明                                                                                                                               |
| ---------------------- | --------------------- | ------------------- | ---------------------------------------------------------------------------------------------------------------------------------- |
| 上线、下线、联系人发现 | 可用                  | 可用                | 9011/UDP type 1 通告、type 2 应答；ENet 心跳 1016，120 秒无入站关闭                                                                |
| 分组、昵称、状态、签名 | 可用                  | 可用                | 握手 `X_HANDSHARK` 与 `X_CHANGE_INFO` / `X_CHANGE_STATUS` / `X_CHANGE_SIGN`                                                         |

## 必须保持的兼容细节

- 9011 发现报文固定 304 字节，type 1 通告、type 2 应答、type 4 会话 hello；本机广播时 `ip` 填 `0.0.0.0`，路由以 UDP 源地址为准。
- 真实客户端的准入字段（0xa9 起的功能字段）还没有完全还原；本机通告可能被真实客户端忽略，但本机仍可通过对方的通告或 `privateSeeds` 主动连接。
- ENet 会话默认监听 9012/UDP，端口被占用时回退临时端口；对端 ENet 端口只能从通告或种子配置获取，不能写死。
- 私有握手会声明文件与文件夹端口：
  - `FILE_TRAN_TCP_PORT` / `FOLDER_TRAN_TCP_PORT` 写实际监听端口（默认 9013/9014）。
  - `FILE_TRAN_ENET_PORT = 0`，文件只走 TCP。
  - 反向连接使用对端公布的端口号；本机要在 9013/9014 和该端口上都监听。
- 文件 `TASK_ID` 是十进制数字，文件夹 `TASK_ID` 是 GUID 字符串，解析时必须分流。
- 正文按 8 字节分组做 **TEA**（32 轮，delta 0x9e3779b9）块加密，末尾不足 8 字节的部分保持明文；密钥是固定串 `8asfhj@k7*20hbla`。
- `X_SEND_MSG(1004)` 与 `X_QGROUP_SEND_MSG(3011)` 的 `<MSG>` 内是 JSON（`app`、`dt[].txt.t/v`、`ft` 字体、`id`、`type`、`ver`），空格在 XML 层写成 `&nbsp;`，引号写成 `&quot;`。

## 验证方式

- 两个本客户端实例：各自设置 `LANPOST_DATA_DIR`，使用不同的 `privatePort` / `privateEnetPort` / `privateFilePort` / `privateFolderPort`，并互相写入 `privateSeeds`；验证发现、文字、送达/已读、文件、文件夹、群聊、离线状态。
- 真实内网通：确认本机能从 9011 通告或种子建立 ENet 会话，文字收到 1005，文件与文件夹双向完成，群聊消息与成员资料一致。
- 文件发送方看 `startup.log` 是否有文件通道连接记录；没有连接时优先查防火墙与 9013/9014 入站规则。
- 抓包与报文示例见 `docs/protocol-debugging.md`。
