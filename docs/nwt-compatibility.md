# 内网通兼容矩阵与私有通道

目标对端是真实内网通 3.4.3055。文字和文件实际走 2425 上的 IPMSG 兼容通道。9011/ENet 私有通道已经接入客户端（发现监听、ENet 会话、TEA 应用帧、`X_SEND_MSG`），本机样本上的文字联调已通过：会话走到 ready，发出的 `X_SEND_MSG(1004)` 收到 1005 回执。两条通道不混用：私有会话就绪时优先私有，否则一律走 IPMSG。

## 必须保持的兼容细节

- 真实内网通的标准报文也使用 `1@shiyeline` 头，但它不会完成私有聊天握手。版本后缀不能作为“支持 `X_SEND_MSG`”的判断依据；只有 `peer.ready` 为真时才走私有 XML。
- 私有握手会声明文件端口。只实现 TCP 文件传输时：
  - `FILE_TRAN_TCP_PORT` 设为实际监听端口（默认 2425）。
  - `FILE_TRAN_ENET_PORT` 必须设为 0。
  - 广告一个有效的 ENet 端口会让对端选择私有 UDP 通道，然后一直等待我们并未实现的连接。
- 文件拉取请求的版本必须是 `1`，不能带 `@shiyeline`。扩展域是 `packetID:fileID:offset:`，全部十六进制，结尾带冒号。
- 真实内网通可能回传自己的文件标识。发送端匹配顺序是 packetID + 对端 IP、文件 ID、该对端最新的 `offered`/`transferring` 任务；最后一种是为兼容对端标识不一致准备的兜底。
- 文件邀请和文字都优先使用 GBK；只有 GBK 不可用时才使用 UTF-8 并设置 `IPMSG_UTF8OPT(0x800000)`。
- 广播 `BR_ENTRY` 的头部是 `1@shiyeline`，种子单播使用版本 `1`；抓包时不要只过滤版本 `1`。

## 私有通道（客户端已接入，文字联调已通过）

内网通的私有通道和 2425 兼容通道是两套机制：

- 9011/UDP 上是 304 字节的二进制发现报文，类型 1/2，包含 IP、端口、企业标识和两个 65 字节块。接收方要求长度、端口字段、两个 65 字节块（非全零且互不相等）以及 0xa9 起的 9 个功能字段通过本机功能表检查。
- 发现后建立 ENet 可靠 UDP 会话（9012/UDP 或临时端口），命令字节是 ENet 的 CONNECT、VERIFY_CONNECT、SEND_RELIABLE、SEND_FRAGMENT，字段大端。
- 会话内第一条应用报文是 304 字节的类型 4 hello（明文，结构与发现报文相同），之后是 `[u32 总长][u32 命令号][正文]`，正文是 UTF-8 XML。
- 正文按 8 字节分组做 **TEA**（32 轮，delta 0x9e3779b9）块加密，每组独立处理，末尾不足 8 字节的部分保持明文。密钥是 `.rdata` 里的固定串 `8asfhj@k7*20hbla`（虚拟地址 0x9ef1c8），与本机标识、企业标识无关。
- `X_SEND_MSG(1004)` 与 `X_QGROUP_SEND_MSG(3011)` 的 `<MSG>` 内是 JSON（`app`、`dt[].txt.t/v`、`ft` 字体、`id`、`type`、`ver`），空格在 XML 层写成 `&nbsp;`，引号写成 `&quot;`。
- 私有文件的数据通道是明文，端口来自 `X_HANDSHARK` 的 `FILE_TRAN_TCP_PORT`。消息帧是 `u32 总长 + u32 版本(1) + u32 类型`，类型 1/2/3/4 分别是 HELLO、ACK、PATH、DATA，另有类型 100 的窗口帧用于反向推送图片。
- 群组、共享文件柜和远程协助依赖同一套通道；本客户端已接入文字、文件和图片，群组等能力未接入。`FILE_TRAN_ENET_PORT = 0`，文件只走 TCP。

- 已验证：状态按 `connecting → verifying → handshaking → ready` 推进；`sendText('127.0.0.1', 424242, '联调测试：私有通道')` 发出的 `X_SEND_MSG(1004)` 收到 1005 回执（`onAck` 424242）。

## 验证方式

- 真实内网通回归重点：发现、文字、文字回执、双向文件、文件拒绝表现。
- 私有通道联调：样本以 `D:/wlr/ai/nwt-re/extracted` 为工作目录启动，占用 UDP 9011/9012；用 `PrivateService` 连 `127.0.0.1:9012`，观察 `onState` 是否到 `ready`、`onAck` 是否收到 1005。当前结论是 ready 与 1005 都已验证，见上一节。
- 文件发送方看 `startup.log` 是否有 `收到取文件连接: IP:端口`；没有这一行说明 TCP SYN 没有到达文件服务，优先查防火墙或安全软件入站规则。
- 有连接但出现 `忽略未知的取文件请求` 时，检查 `GETFILEDATA` 的版本、十六进制字段和 32 位 seq。
- 抓包和报文示例见 `docs/protocol-debugging.md`，标准协议见 `docs/ipmsg-protocol-zh.md`。
