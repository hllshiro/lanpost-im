# 内网通数据库与加密

本文记录内网通 3.4.3055 的本地数据库格式与加密方式，用于把账号、群、聊天记录与文件记录迁移到本客户端。结论由静态逆向与真机进程验证得到，解密结果能通过 SQLite 的 `integrity_check`。

## 1. 数据目录

数据根目录是安装目录下的 `Syl`：

| 文件                          | 内容                                                     | 是否加密 |
| ----------------------------- | -------------------------------------------------------- | -------- |
| `data/acc`                    | 32 位十六进制用户标识，等于协议里的 `USER_ID`            | 否       |
| `data/qrp`                    | 群资料与群成员（`QGroupInfo_<acc>`、`QGroupUser_<acc>`） | 否       |
| `data/sc`                     | 本机状态：版本、积分、颜色名、排序名                     | 是       |
| `cache/db/nr`                 | 聊天记录、群聊天记录、文件记录、组织架构                 | 是       |
| `cache/db/ol`                 | 离线消息与离线文件记录                                   | 是       |
| `cache/db/sd`、`cache/db/shr` | 共享文件清单与下载记录                                   | 否       |
| `cache/cfg/Option.xml`        | 本机资料、头像 md5、企业标识                             | 否       |
| `cache/face/<md5>`            | 头像文件，文件名即 md5                                   | 否       |

表名统一带账号后缀 `_<acc>`，聊天与文件记录再按分片加 `_<n>`，分片号是客户端内部分配的序号。

## 2. 加密方式

加密在 SQLite 的分页层完成，每个库文件由独立的页组成：页号从 1 开始，页内使用 AES-128-CBC，无填充，无 HMAC。

- 页大小取自解密后的 SQLite 头部偏移 16 的两个字节（本机样本为 1024）。
- 主密钥固定为 `e07eaa7a612524e130afb6bb62c562be`，由客户端内置口令 `ZpkL9ejq` 经 MD5 迭代派生；同一版本的所有数据库共用。
- 每页密钥：`MD5(主密钥 ‖ 页号小端 4 字节 ‖ "sAlT")`。
- 每页初始向量：先把页号加一作为状态，连续 4 轮执行 `state = state * 0x9ef4 mod 0x7fffff07`，每轮把状态的小端 4 字节写进 16 字节缓冲，最后取 `MD5(缓冲)`。
- 解密时每页单独初始化，不跨页链接。

第一页的数值可以用于自检：密钥 `61dc201dec7b5b9d3254f5288a87f92f`，初始向量 `20d7420f9c37a35dca6fe92a1c6999a9`，解出的页头应是 `SQLite format 3\0`。

实现见 `src/main/store/nwt-db.ts`，`decryptNwtDatabase` 会自动从页头读取页大小并逐页解密。

## 3. 表结构

`nr` 解密后的表（`<acc>` 为用户标识，`<n>` 为分片号）：

| 表                                                 | 主要字段                                                                                                                                            | 说明                 |
| -------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------- | -------------------- |
| `ChatRecord_<acc>_<n>`                             | `FromUserId`、`FromUserName`、`ToUserId`、`ToUserName`、`PeerUserId`、`MsgId`、`HasImage`、`MsgTime`、`MsgData`、`MsgText`、`RecordType`、`Receipt` | 一对一聊天记录       |
| `QGroupChatRecord_<acc>_<n>`                       | 同上                                                                                                                                                | 群聊天记录           |
| `FileRecord_<acc>_<n>`                             | `FileId`、`FileType`、`FileMedia`、`FileSize`、`FilePath`、`FileName`、`RecordType`                                                                 | 一对一文件记录       |
| `QGroupFileRecord_<acc>_<n>`                       | 同上                                                                                                                                                | 群文件记录           |
| `AllFileRecord_<acc>`                              | 同上                                                                                                                                                | 全部文件记录汇总     |
| `FgChatRecord_<acc>_<n>`、`FgFileRecord_<acc>_<n>` | 与上面同构                                                                                                                                          | 另一组记录，字段一致 |
| `OrgStruct_<acc>`                                  | `UpdateTime`、`OnlineTime`、`Type`、`Id`、`Data`                                                                                                    | 组织架构缓存         |
| `Version_<acc>`                                    | `Version`、`Upgrade`                                                                                                                                | 数据版本             |

`MsgData` 是 UTF-8 的 JSON：`type`、`ver`、`id` 描述消息本身，`dt` 是按顺序排列的正文片段，文字片段为 `{"txt":{"t":"normal","v":"…"}}`，文件片段为 `{"file":{"t":"recv_file","v":"<路径>"}}`，`ft` 是字体与颜色。`MsgText` 是同一段文字的纯文本摘要。

`ol` 解密后的表：

| 表                            | 主要字段                                             |
| ----------------------------- | ---------------------------------------------------- |
| `OfflineChatRecord_<acc>`     | `ToUserId`、`MsgData`、`MsgTime`、`MsgText`、`MsgId` |
| `OfflineFileTranRecord_<acc>` | `ToUserId`、`FilePath`、`Time`、`Type`               |

## 4. 验证

对 `nr`、`ol`、`sc` 三个库用上述参数整库解密，写成文件后用 SQLite 打开：

- `PRAGMA integrity_check` 均为 `ok`。
- `nr`：205 张表，含 12 条文件记录、多组聊天记录（其中一组 17 条、一组 5 条）与 6 条群聊天记录。
- `ol`：3 张表；`sc`：8 张表。

## 5. 导入到本客户端

设置页选择内网通安装目录后，先解密并汇总，再由弹窗勾选范围：

- 账号与资料（用户标识、昵称、公司、部门、签名、头像）整块导入；关掉后只导群与历史。
- 群资料与群成员整块导入；关掉后群历史也不出现。
- 聊天记录按会话勾选，可搜索、可全选/全不选、可按最近天数过滤。

落库规则：

- 一对一会话按对端用户标识建键，消息写进 `direct:<用户标识>`；地址只属于当前会话，换地址不会多出一条会话。
- 群会话按群号写进 `group:<群号>`；已有会话保留当前标题，不用历史里的旧昵称覆盖。
- 消息按 `MsgId` 去重，写进 `messages.nwt_id`，重复导入只累加跳过数。
- 文字与表情按原顺序写进 `meta.segments`；内网通时间戳是 Unix 秒，导入时换算成毫秒。
- 文件记录生成文件卡片：记录里的路径在本机存在时状态为 `done`，否则为 `missing`，界面显示“文件不在这台电脑”。

## 6. 注意

- 主密钥与派生规则只对 3.4.3055 验证过；换版本需要重新确认。
- 没有完整性校验，页内容损坏后仍会解出数据，迁移时以 `integrity_check` 判定是否可信。
- 库里的文件路径是发送方或接收方的本机绝对路径，迁移时只应保留文件名。
