# 私有协议模式下的能力取舍

本文件记录从 v0.1.1 的 IPMSG 能力迁移到 NWT 私有协议时，哪些能力已经由私有协议覆盖，哪些暂不支持。避免后续把“协议没有对应字段”误当成回归缺陷。

## 已由私有协议覆盖

| v0.1.1 能力 | 私有协议现状 | 说明 |
| ----------- | ------------ | ---- |
| 单文件发送/接收 | 已覆盖 | `X_SEND_FILE(1009)` + TCP proto=1；支持直连、反向连接、进度 |
| 文件夹发送/接收 | 已覆盖 | `X_SEND_FOLDER(1013)` + TCP proto=2；发送方连接收方文件夹端口 |
| 图片/剪贴板图片 | 已覆盖 | 私有图片卡片 + 文件通道；本地复制粘贴仍可用 |
| 标准已读回执 | 已覆盖 | `X_SEND_MSG_ACK(1005)` 送达、`X_SEND_RECEIPT(1006)` 已读 |
| 联系人资料请求 | 已覆盖 | 握手 `X_HANDSHARK`、`X_CHANGE_INFO`、`X_CHANGE_STATUS`、`X_CHANGE_SIGN` |
| 在线状态/签名/分组 | 已覆盖 | 私有 profile 与 `X_CHANGE_*` |
| 广播/多选群发 | 已实现（客户端逐人投递） | 只发给在线且私有会话就绪的联系人；不是协议级广播 |

## 暂不支持

| 能力 | 现状 | 原因 | 后续 |
| ---- | ---- | ---- | ---- |
| 密封消息/启封 | 未实现 | 私有 `X_SEND_MSG` 没有密封/启封字段；TEA 只是传输加密 | 需要真实客户端抓包确认是否存在隐藏字段 |
| 文件取消/暂停/拒绝的对端通知 | 本地生效 | `X_OPERATE_SEND_FILE` / `X_OPERATE_RECV_FILE` 的 `OP` 取值只确认了 `2=接受/开始`；暂停、继续、取消、拒绝未知 | 用真实客户端逐项触发并抓包，补齐 OP 表 |
| IPMSG 标准目录流 | 不适用 | IPMSG 层已移除；文件夹走私有 proto=2 | 无需恢复 |
| IPMSG 剪贴板附件 | 不适用 | IPMSG 层已移除；图片走私有图片卡片 | 无需恢复 |
| IPMSG 标准已读/主机列表/资料请求 | 不适用 | IPMSG 层已移除；私有 1005/1006 与握手覆盖常用场景 | 无需恢复 |
| 拨号模式 | 明确不恢复 | 用户要求排除；当前用 `privateSeeds` 处理广播不可达 | 需要时再评估 |
